# 本地多租户请求准入网关（Go）

一个用**内存状态 + 本地追加日志**模拟真实调用的请求准入网关。它在并发请求下给出
**一致且可解释**的鉴权、限流与配额扣减结论，并通过本地事件日志支持进程重启后的
口径恢复。全部时间源可注入，单元测试不依赖任何真实等待。

## 目录结构

```
internal/
  clock/    可注入时间源：RealClock 与 FakeClock（测试零等待）
  model/    领域类型：请求、令牌声明、判定结论、拒绝码
  auth/     令牌认证（缺失/未知/过期/撤销）与作用域授权（层级越权判定）
  quota/    每租户令牌桶（速率）+ 信号量（并发槽），判定与记账原子
  audit/    审计流水：标准日志输出 + 内存留存（输入 / 判定依据 / 最终配额）
  journal/  JSON Lines 追加日志，fsync 落盘，重启按序重放
  gateway/  编排：幂等去重 -> 认证 -> 授权 -> 原子配额判定 -> 审计/持久化
main.go     可运行的本地演示，覆盖全部拒绝码、配额、幂等与重启恢复
```

## 准入判定流程

`Gateway.Admit(req)` 严格按下列顺序短路，**任何拒绝都发生在配额记账之前**，
因此越权、过期、撤销、超额的请求绝不消耗速率令牌或并发槽：

1. **幂等去重**：`IdempotencyKey` 非空时，命中在途/历史结论则直接返回原结论
   （`Replayed=true`），不重新鉴权、不重复扣配额。相同键的**并发**请求会等待
   首个请求的结论，得到与首个请求完全一致的结果。
2. **认证（Authentication）**：缺失 / 无法识别 / 已过期 / 已撤销的令牌被拒绝。
3. **授权（Authorization）**：令牌作用域不满足所需作用域（越权）被拒绝。
4. **配额（Quota）**：在每租户临界区内一次性完成“令牌桶填充 → 判速率 → 判并发
   → 记账”。

请求实际执行结束后调用 `Gateway.Finish(requestID, executeFailed)`：

- 无论成功失败，**并发槽都归还**；
- `executeFailed=true`（执行失败）时**额外退还速率令牌**，即执行失败不计费；
- `Finish` 幂等，重复调用不会重复释放，杜绝配额/槽位泄漏。

## 配额模型

每个租户独立配置（互不影响）：

| 配置             | 含义                                                   |
|------------------|--------------------------------------------------------|
| `RatePerSecond`  | 令牌桶填充速率，同时也是桶容量（允许的瞬时突发上限）   |
| `MaxConcurrent`  | 在途并发槽数量；已放行但未 `Finish` 的请求占用一个槽   |

- **速率（令牌桶）**：懒填充，按 `(当前时刻 - 上次填充时刻) × RatePerSecond`
  补令牌，封顶为容量。每次放行消耗 1 个令牌；桶中不足 1 个时返回
  `RATE_LIMITED`。
- **并发（信号量）**：已占用槽达到 `MaxConcurrent` 时返回 `CONCURRENCY_FULL`。
- 速率与并发是两个**相互独立、可区分**的拒绝原因；判定顺序为先速率后并发。

### 并发安全与不超发

- 每个租户一把互斥锁，租户之间互不阻塞，实现**租户间状态隔离**。
- `TryAcquire` 在该锁内完成“判定 + 记账”，因此并发下严格满足：
  放行数 `= min(桶内令牌, 空闲并发槽)`，不会超发、不会部分扣减；
  被拒绝路径在任何状态变更之前返回，不泄漏令牌或槽位。
- 并发压测（`go test -race`）断言放行数精确等于容量、最终在途数精确一致、
  高并发“获取-释放”后在途归零（无泄漏）。

## 鉴权与拒绝码语义

作用域为层级模型：`admin > write > read`，持有高等级作用域可访问低等级资源。

| 拒绝码             | 触发情形                                 | 是否消耗配额 |
|--------------------|------------------------------------------|--------------|
| `MISSING_TOKEN`    | 请求未携带令牌                           | 否           |
| `UNKNOWN_TOKEN`    | 令牌无法识别                             | 否           |
| `TOKEN_EXPIRED`    | 令牌已过有效期（基于注入时钟判定）       | 否           |
| `TOKEN_REVOKED`    | 令牌已被显式撤销                         | 否           |
| `SCOPE_DENIED`     | 已认证但作用域不足（越权）               | 否           |
| `RATE_LIMITED`     | 租户速率令牌不足                         | 否（被拒）   |
| `CONCURRENCY_FULL` | 租户在途并发槽已满                       | 否（被拒）   |
| `UNKNOWN_TENANT`   | 租户未配置配额（内部防御，默认不放行）   | 否           |

放行时 `Decision.Allowed=true`、`RejectCode` 为空，并携带判定时刻的
`RateRemaining / RateCapacity / ConcurrencyInUse / ConcurrencyMax` 配额快照，
使结论“可解释”。

## 幂等与重启恢复

- 携带相同 `IdempotencyKey` 的重复提交（串行或并发）只产生一次真实配额记账；
  后续命中返回原结论。被拒绝的幂等请求不保留副作用，资源释放后同键可重新判定。
- 每次放行 / 结束都以 JSON Lines 事件（`admit` / `finish`）追加到本地日志并
  `fsync`。进程重启后用**全新内存状态**先注册租户、再 `Restore()` 按序重放，
  即可恢复速率令牌、在途槽与幂等记录，保证“同一输入的判定与统计口径一致”。
- 日志末尾若因崩溃出现写了一半的半行，重放会安全忽略。

> 说明：本工程为本地模拟，令牌在演示中由内存签发；生产环境中令牌/租户配置应来自
> 受控配置中心或鉴权服务。重放只恢复“配额记账状态”。

## 审计日志

每次判定输出一行结构化日志，包含**请求输入**（脱敏令牌、所需作用域、幂等键）、
**判定依据**（basis 文案）以及**最终配额**快照，例如：

```
[audit] request_id=req-... tenant=tenant-a token="tok***123" scope=read idem="k-1"
  => allowed=false code=RATE_LIMITED basis="quota check failed: RATE_LIMITED"
  | rate=0.000/3.000 concurrency=2/2 replayed=false at=2026-09-22T10:00:00.000Z
```

## 本地验证

要求 Go 1.25+。

```bash
# 1. 运行端到端演示（FakeClock，无真实等待；审计日志输出到 stderr）
go run .

# 2. 全部单元测试
go test ./...

# 3. 带竞态检测 + 多轮重复（推荐，覆盖并发超发/泄漏不变量）
go test -race -count=3 ./...

# 4. 只跑高并发不超发压测
go test -race ./internal/quota/ -run TestConcurrent
go test -race ./internal/gateway/ -run TestConcurrent

# 5. 静态检查与格式化
go vet ./...
gofmt -l .   # 无输出即已格式化
```

### 测试覆盖一览

- 正常放行、作用域层级授权；
- 缺失 / 未知 / 过期 / 撤销 / 越权等拒绝码可区分，且拒绝前后配额快照不变；
- 速率耗尽、并发打满、令牌按时间回补、执行失败退还速率令牌且释放并发槽；
- 租户间配额相互隔离；
- 幂等串行/并发重复提交只记账一次、并发重复得到一致结论、被拒后可重试；
- 重启重放恢复在途槽与速率口径，半行日志容错；
- 全部基于 `FakeClock` 驱动，无 `time.Sleep`、无真实等待。
