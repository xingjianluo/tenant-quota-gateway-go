# tenant-quota-gateway-go

本地多租户请求准入网关：以本地状态模拟真实调用，在并发请求下保证鉴权、限流与配额扣减的**一致且可解释**的结论；通过快照 + 提交日志把结论持久化到本地文件，**进程重启前后表现得像同一个网关在继续服务**。

## 架构

```
cmd/gateway            演示程序（本地完整调用链，默认开启本地持久化）
internal/clock         可注入时间源（Real / Fake），测试不依赖真实等待
internal/auth          令牌鉴权与作用域判定
internal/quota         按租户隔离的速率 + 并发 + 总量配额（含快照导出/恢复/在途结算）
internal/persist       本地持久化：原子快照 snapshot.json + 仅追加提交日志 events.log
internal/gateway       准入编排：鉴权 → 配额 → 执行 → 记账 → 提交，幂等去重 + 审计流水 + 重启恢复
```

调用链：`Gateway.Admit(req)` → `auth.Authorize` → `quota.Acquire`（原子判定+记账）→ `Handler` 执行 → 锁内原子 `Finish`（释放并发槽，失败归还配额）→ 结论写提交日志（fsync）→ 追加审计流水并输出日志。

## 重启恢复语义

接入 `Gateway.AttachStore(store, auditRetain, checkpointEvery)` 后，网关把状态写到本地目录（默认 `./.gateway-state`）：

- **提交顺序（write-ahead）**：判定结论先 fsync 落盘（`events.log` 追加一行 JSON），再返回给调用方。因此进程在任意时刻被 SIGKILL，重启后对某个请求只有两种状态：
  - 找不到该请求 → 结论未提交，这次请求视同未发生，调用方安全重试；
  - 找到该请求 → 返回与首次**完全一致**的结论（`DUPLICATE`，reason 中带原判定码与首次最终配额）。
- **处理途中被强杀**：`Acquire` 已预扣配额/占槽，但结论还没来得及落盘。恢复时先重建出崩溃瞬间的最终计数器状态（快照 + 日志重放的合并结果），其中仍标记 `InFlight>0` 的占用一律属于"崩溃前还在执行、结论未提交"的请求，统一按**未发生**结算——释放并发槽、归还预扣配额与速率令牌。已提交的成功扣减不回滚，未提交的在途扣减不残留：不会多扣，也不会有槽位被永久占住。
  - **检查点时刻有请求在途也算清**：检查点快照会如实带上当时的在途占用（`InFlight>0`、含预扣的 `Used`）。若此后没来得及再提交就崩溃，恢复时快照状态同样参与上述结算——在途占用不会因为"已经被打进快照"而被当成已确认用量保留下来。
  - **只回滚一次**：结算只作用于每次启动时从磁盘重建出的内存状态，本身不落盘；即使刚恢复又崩溃、或反复空重启，下次恢复仍从同一份磁盘状态重做一次同样的结算，结果一致，不会出现重复退款。同一次崩溃崩掉多个在途请求时，按实际在途数逐笔归还。
- **崩溃尾部容忍**：仅追加日志最后一行可能因崩溃只写了一半。恢复时只容忍"文件末尾的半行"；中间出现坏行视为日志损坏并报错，绝不静默跳过。
- **检查点原子性**：`snapshot.json` 以"临时文件 + fsync + rename"替换，崩溃后只可能是旧版或新版。若快照已落盘但日志截断前崩溃，重放时按序号水位（`LastSeq`）跳过已包含在快照中的旧事件，审计不会重复、状态不会回退。
- **令牌桶跨重启**：持久化的是判定时刻的桶水位（tokens + lastFill）。恢复后令牌桶按注入时钟继续补充；已消耗的总量配额、并发与已处理结论接着延续，不回到初始状态。

### 哪些状态被保留 / 不保留

| 状态 | 是否保留 | 说明 |
|---|---|---|
| 各租户总量配额已用量 / 剩余量 | 保留 | 成功扣减接着算；失败退款与未提交在途扣减不残留 |
| 各租户速率令牌桶水位 | 保留 | tokens 与 lastFill 精确保留，重启后按时间继续补充 |
| 已提交的幂等结论（含鉴权失败、配额拒绝） | 保留 | 任意已处理请求重放都判 `DUPLICATE`，结论一致、不二次扣减 |
| 审计流水 | 保留最近 `auditRetain` 条尾部 | 窗口内序号连续、可查请求输入/判定依据/最终配额；序号水位（seq）始终保留，新记录不会从 1 开始 |
| 崩溃瞬间在途请求的槽位与预扣 | 按"未提交"回滚 | 槽位释放、配额与令牌归还，请求可作为新请求重试；检查点快照里的在途占用同样回滚，结算幂等（反复重启不重复退款） |
| 令牌与配额配置、令牌仓库内容 | 不持久化 | 视为部署配置，重启时由程序重新装载（见"兼容范围"） |
| 崩溃瞬间在途请求的下游副作用 | 不管辖 | 网关只保证自身记账一致；下游是否幂等由 Handler 自身负责 |

### 一致性与启动开销的取舍

- 选择"**每条提交 fsync + 周期性快照截断日志**"而不是"每次判定全量快照"：每条 fsync 保证已返回的结论必不丢；快照每 `checkpointEvery`（默认 256）条事件打一次并截断日志。
- 这样启动恢复只需读取**一份快照 + 至多一个检查点间隔的日志**，重放工作量被常数限定，**不随历史请求总数增长**（`TestRecoveryBoundedByCheckpoint`：500 条历史恢复重放 ≤ 8 条事件，约 40ms）。
- 代价是审计只保留尾部窗口（默认 4096 条）。更早的审计被挤出窗口，但幂等表与配额不丢——因为幂等表整体存在快照里，计数器取每租户最后事件的精确快照，不依赖逐事件重放。调大 `auditRetain` 可换更长查询窗口，代价是快照文件变大。
- 这是**单进程本地存储**，不支持多个网关进程并发打开同一目录，也不依赖任何外部服务或数据库。

### 兼容范围

- 状态目录绑定同一组**租户配额配置与令牌定义**。重启时需重新装载相同的 `quota.Limit` 与 `auth.Token`；配置变更（如改 TotalQuota/Burst）后旧快照仍可读取，但统计口径以新配置重新解释剩余量，不保证与变更前逐字节一致。
- 持久化格式为版本化前的本地 JSON（snapshot.json 与 JSONL 事件日志），面向单机反复重启，不承诺跨大版本的文件格式兼容。

## 配额模型

每个租户独立配置 `quota.Limit`，状态完全隔离，互不影响：

| 字段 | 含义 | 模型 |
|---|---|---|
| `RatePerSec` / `Burst` | 速率限制 | 令牌桶：按注入时钟经过时间补充，上限 `Burst` |
| `MaxConcurrent` | 并发槽上限 | 执行期间占用一个槽，结束（无论成败）在锁内原子释放 |
| `TotalQuota` | 成功执行总量配额 | `Acquire` 时预扣，执行失败时归还 |

一致性保证：

- **判定与记账原子**：`Acquire` 在单把互斥锁内完成"检查令牌/并发槽/配额 + 扣减"，任何并发下都不会超额放行（`internal/quota` 压测验证：500 并发竞争 50 配额，放行数恒等于 50）。
- **拒绝零副作用**：任一条件不满足即拒绝，不产生任何记账；拒绝结论同样落盘并进入幂等表。
- **失败不泄漏**：执行失败归还预扣配额与令牌；并发槽无论成败都释放。
- **幂等**：相同 `RequestID` 的重复提交（含并发提交、含跨重启）共享首次判定，返回 `DUPLICATE`，不重复扣减、不重复执行下游。
- **可重放**：相同配置 + 相同输入序列，在新实例（模拟进程重启）上重放得到完全一致的判定序列与统计口径（见 `TestReplayDeterminism`）。

## 鉴权与拒绝码语义

令牌（`auth.Token`）承载 `TenantID`、`Scopes`、`ExpiresAt`、`Revoked`。鉴权失败**不触碰任何配额**。

| 判定码 | 含义 |
|---|---|
| `EXECUTED` | 鉴权通过、配额内、下游执行成功 |
| `EXEC_FAILED` | 下游执行失败，配额与令牌已归还，并发槽已释放；`Reason` 原样保留下游返回的真实错误（见下文"执行失败的判定依据"） |
| `REJECT_TOKEN_UNKNOWN` | 令牌不存在 |
| `REJECT_TOKEN_EXPIRED` | 令牌已过期（按注入时钟判定） |
| `REJECT_TOKEN_REVOKED` | 令牌已被撤销 |
| `REJECT_SCOPE_DENIED` | 令牌不具备请求的作用域 |
| `REJECT_RATE_LIMITED` | 令牌桶为空，速率超限 |
| `REJECT_CONCURRENCY_LIMITED` | 并发槽已满 |
| `REJECT_QUOTA_EXHAUSTED` | 总量配额耗尽 |
| `DUPLICATE` | 重复提交（含跨重启），结果为首次判定的副本（`Reason` 中含原判定码） |

## 执行失败的判定依据

下游 `Handler` 返回的 `error` 会**原样**写入本次判定的 `Reason`（不是一句笼统的套话），并随之进入审计流水与提交日志。因此：

- 首次判定的 `Decision.Reason`、审计记录里的 `Reason` 都是下游真实错误文本（如 `downstream boom: connection refused`），能直接看出这一次为什么失败；
- 该结论持久化后跨重启保留：恢复出的审计记录仍带原始错误，重复提交返回 `DUPLICATE`（`Reason` 为 `duplicate of EXEC_FAILED`），首次结论中的真实错误可在幂等表/审计中回查；
- 失败请求的配额与令牌已归还、并发槽已释放，退款口径跨重启一致。

## 审计与日志

每次判定（**包括首次判定与重复判定**）追加一条 `AuditRecord`（序号、时间、类型、请求 ID、令牌、租户、作用域、判定码、原因、配额快照），可通过 `Gateway.Audit()` 读取。重复判定也各占一个连续序号，因此跨重启重复请求的记录可查、不乱序：

```
audit seq=1 req=demo-1 token=tok-alpha scope=invoke tenant=alpha code=EXECUTED reason="ok" usage={tokens:99.00 inflight:0 used:1 remain:7}
audit seq=70 req=demo-1 token=tok-alpha scope=invoke tenant=alpha code=DUPLICATE reason="duplicate of EXECUTED" usage={tokens:99.00 inflight:0 used:1 remain:7}
```

## 本地验证

```bash
# 全部单元测试（含 race 检测；测试使用 Fake 时钟，不依赖真实等待、不依赖外部服务）
go test ./... -race

# 运行演示：正常、越权、幂等、并发压测、租户隔离与审计汇总（状态写入 ./.gateway-state）
go run ./cmd/gateway -reset
# 立刻再跑一次（不重置）：同一批输入全部判 DUPLICATE，配额用量与首次完全一致
go run ./cmd/gateway
# 审计里同时保留首次结论与本次重复结论；seq 连续
ls ./.gateway-state   # snapshot.json（检查点后生成）+ events.log

# 从头验证
go run ./cmd/gateway -reset
```

测试覆盖（新增重启恢复类均用可注入 Fake 时钟，无真实等待）：

- 原有：正常放行、未知/过期/撤销令牌、越权作用域、速率/并发/配额三类超额拒绝、执行失败退款、幂等重复（含并发重复）、并发压测不超发不泄漏、租户隔离、重放确定性、审计内容。
- `internal/quota`：快照导出/恢复后用量连续、崩溃在途结算（释放槽位 + 归还预扣，已提交不回滚）。
- `internal/persist`：快照往返与原子替换、事件日志追加/截断、末尾半行容忍、中间坏行报错、首次启动无快照。
- `internal/gateway`：
  - 重启后已扣配额/剩余额度连续，跨重启继续判定直至耗尽；
  - 重启后重复请求判 `DUPLICATE`、结论与首次一致、不二次扣减，且重复判定写入连续审计（含请求输入/依据/最终配额）；
  - 处理途中 SIGKILL：在途槽位释放、预扣归还、未提交请求可重新执行；已提交后崩溃则判重复、不双扣；
  - **在途 + 检查点 + 强杀链路**：请求卡在下游期间打了检查点再崩溃，重启后在途占用（槽位/配额/令牌）全部回滚、已提交扣减保留；唯一并发槽被在途占满时新请求被拒、恢复后同请求可放行；
  - **混合与反复崩溃**：同一次崩溃崩掉多个在途 + 已完成混合时用量严格等于已完成部分；反复"在途+检查点+强杀"多周期与多次空重启结论一致、不重复退款；刚打完检查点（日志为空）立即崩溃时全部回滚到初始账目；
  - **执行失败判定依据**：下游真实错误原样进入结论与审计、跨重启恢复后仍可查，失败退款口径不变；
  - 检查点已落盘但日志未截断时崩溃：旧事件不重放成重复审计、状态不回退、序号接水位；
  - 历史增长到 500 条后恢复仍只重放有界事件、审计尾部窗口保留且序号连续；
  - 执行失败退款、限流拒绝、鉴权失败等不同结论跨重启的重复口径一致。

`go test -v` 的日志中，崩溃恢复类用例会打印每次恢复后的配额账目（tokens/inflight/used/remain），可直接核对回滚结果。
